# Implementation Plan

- [x] 1. Foundation: データベーススキーマとシードデータ
- [x] 1.1 MonthlyMaterialモデル・enum追加とマイグレーション生成
  - `MonthlyMaterialCategory`（salesFloorMeeting/pop）・`MonthlyMaterialSourceType`（upload/google）・`MonthlyMaterialTargetingScope`（all/countries/companies）の3 enumと`MonthlyMaterial`モデルをPrismaスキーマに追加する
  - `category`・`year`・`month`の組み合わせに一意制約、`category`に索引を設定する
  - マイグレーションを生成・適用し、DB上に一意制約付きの新規テーブルが存在することを確認する
  - _Requirements: 1.4, 9.1, 9.2_

- [x] 1.2 デモシードデータ追加
  - 売場検討会・POPそれぞれについて、2026年9月分のデモ資料（既存のサンプルPDFデータURLを使用）をシードスクリプトに追加する
  - シード実行後、両カテゴリの一覧取得で各1件のデモ資料が返ることを確認する
  - _Requirements: 2.1_
  - _Depends: 1.1_

- [x] 2. Foundation: ドメイン型とバリデーション
- [x] 2.1 型定義の追加
  - `MonthlyMaterial`・`CreateMonthlyMaterialInput`・カテゴリ列挙をドメイン型として定義し、既存のドキュメント管理機能の型に依存しない独立した型とする
  - _Requirements: 1.4_

- [x] 2.2 入力バリデーションの実装
  - 登録方式（アップロード／Googleリンク）ごとに、年・月・ファイルまたは共有リンクURL・公開範囲の必須項目を検証するスキーマを実装する
  - PDF形式・サイズ上限超過・Googleドキュメント/スプレッドシート/スライド以外のURLパターンが、それぞれ検証エラーとして検出されることを単体テストで確認する
  - 公開範囲で「国単位」「販社単位」を選んだのに1件も選択されていない場合に検証エラーになることを単体テストで確認する
  - _Requirements: 10.1, 10.2, 10.3, 10.4, 11.1, 11.2, 12.1, 12.2, 12.3, 12.4_
  - _Depends: 2.1_

- [x] 3. Core: データアクセス層（Mapper・Service）
- [x] 3.1 Mapper層の実装
  - DBレコードとドメイン型を相互変換する処理と、公開範囲3要素（全体公開／国単位／販社単位）の変換処理を実装する
  - 登録方式（アップロード／Google）と実データの不整合を検出した場合に例外を送出することを単体テストで確認する
  - _Requirements: 1.4_
  - _Depends: 2.1_

- [x] 3.2 Service層の実装（可視性フィルタ・CRUD・年月一意性）
  - カテゴリを必須の絞り込み条件とした一覧取得（海外販社側の公開範囲フィルタ適用版／ヘルプデスク側の全件版）を実装する
  - 資料の作成・更新・削除処理を実装し、年月の降順で一覧が返ることを保証する
  - 一覧取得時、他カテゴリの資料が結果に混入しないことを単体テストで確認する
  - 公開範囲（全体公開／国単位／販社単位）の3分岐それぞれで正しく可視性が判定されることを単体テストで確認する
  - 同一カテゴリ内で既存の年月と重複する年月を作成・更新しようとした場合に、専用のエラーとして検出されることを単体テストで確認する
  - _Requirements: 1.3, 2.1, 2.2, 3.1, 3.2, 3.3, 3.4, 9.1, 9.2, 13.2_
  - _Depends: 1.1, 3.1_

- [x] 4. Core: アプリケーション層（認可・Server Actions）
- [x] 4.1 認可付きデータアクセス層の実装
  - 海外販社側セッションからは自社への公開範囲が及ぶ資料の読み取りのみ、ヘルプデスク側セッションからは全件の読み取りと書き込み全操作を許可する
  - 海外販社側セッションで書き込み操作を試みた場合に拒否されることを確認する
  - _Requirements: 3.1, 6.2_
  - _Depends: 3.2_

- [x] 4.2 Server Actionsの実装（登録・更新・削除）
  - フォーム入力を検証したうえで資料を作成・更新・削除する処理を実装し、Google共有リンク登録時は埋め込み用URLをサーバー側で再計算してからクライアント入力を上書きする
  - 保存・削除が成功した場合に、海外販社側・ヘルプデスク側それぞれの対応するカテゴリのルートが再検証され、直後の再取得で最新状態が反映されることを確認する
  - _Requirements: 8.4, 9.1, 11.3, 11.4, 11.5, 13.3, 14.3_
  - _Depends: 2.2, 4.1_

- [x] 5. Core: 共通UIコンポーネント
- [x] 5.1 資料登録・編集フォームの実装
  - 対象年・対象月・登録方式（ファイルアップロード／Googleリンク）・ファイルまたは共有リンクURL・公開範囲を入力する画面を実装し、送信時にServer Actionsを呼び出す
  - 送信が成功した場合に一覧へ新しい内容が反映されることを確認する
  - 年月が重複しているために保存できなかった場合、他の入力エラーとは異なる専用のメッセージが年・月の入力欄に表示されることを確認する
  - _Requirements: 8.2, 8.3, 9.1, 10.5, 11.1, 11.2, 12.1, 12.2, 12.3, 12.4, 13.1, 13.2, 16.1_
  - _Depends: 4.2_

- [x] 5.2 (P) 資料削除ボタンの実装

  - キャンセル時には何も実行されず、確定時のみ一覧から当該資料が除去されることを確認する
  - _Requirements: 14.1, 14.2, 14.3, 16.1_
  - _Boundary: DeleteMonthlyMaterialButton_
  - _Depends: 4.2_

- [x] 5.3 年月セクション（表示/編集モード切り替え）の実装
  - 1つの年月分の資料について、PDFプレビュー（アップロード型・Google型双方、Google型は読み込み失敗時のフォールバック案内を含む）を表示する表示モードと、5.1のフォーム・5.2の削除ボタンを表示する編集モードを、画面遷移なしで切り替えられるようにする
  - 表示モードのプレビュー領域と同じ箇所の右上に編集モードへ切り替えるボタンを配置する
  - あるセクションを編集モードに切り替えても、他の年月セクションの表示モードには影響しないことを確認する
  - _Requirements: 2.3, 4.1, 4.2, 4.3, 4.4, 5.1, 5.2, 5.3, 5.4, 6.3, 7.1, 7.2, 7.3, 7.4, 16.1_
